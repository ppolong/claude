# 사이드 프로젝트 실험 로그

개인 사이드 프로젝트 실험. 목표는 "완성도 높은 제품"이 아니라 **돈을 낼 사람이 있는지 최대한 빨리 확인**하는 것.

## 운영 방식 (1주 = 1개 실험 사이클)

| Day | 내용 |
|---|---|
| 1 | 시장/경쟁제품 확인 + 수익화 가설 |
| 2 | 최소 기능 설계 |
| 3-4 | MVP 개발 |
| 5 | 테스트 + 실제 사용 시나리오 검증 |
| 6 | 판매 가능 형태 정리 + 가격 가설 |
| 7 | 공개/판매 여부 판단 |

개발이 빨리 끝나면 7일까지 기다리지 않고 바로 시장검증으로 넘어간다. 시장성이 약하면 미련 없이 중단하고 다음 아이템으로 이동한다.

우선순위 기준: **수익 가능성 × 실행 속도 × 초기 비용 × 경쟁 난이도**. 재미보다 돈이 될 가능성 우선.

전제: 개인 GitHub + 개인 장비 + 업무시간 외.

## 원칙 (검증 기준 / 법적 가드레일)

**시장성 체크**: 아이디어 채택 전/전환 전에 "이미 비슷한 걸 개인/소규모로 팔고 있는 사람이 있는가", "기존 official/무료 솔루션이 이미 있는가"를 실제로 찾아본다. 경쟁자가 없다는 것 자체가 반드시 좋은 신호는 아니다(수요가 없어서일 수도 있음) — 타겟 세그먼트가 이 문제를 스스로 언급/검색하는 행동 증거가 있는지까지 확인한다.

**법적 가드레일**: 경쟁 제품을 참고(리서치, UX 벤치마킹, 가격 구조 이해)하는 건 문제 없지만, 코드/UI/문구/브랜드를 그대로 베끼지 않는다. 데이터/규칙을 재사용할 땐 공개적으로 재사용 가능한 라이선스(예: CC-BY, OSI 승인 라이선스)가 명시된 소스만 쓰고 조건(출처 표기 등)을 지킨다.
